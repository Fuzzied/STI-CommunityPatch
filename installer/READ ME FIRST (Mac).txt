Space Travel Idle Community Mod, Mac version
============================================

Thank you for testing this. You are the first person to run it on a Mac, so
this file is longer than it will ever need to be again.

Nothing here has been tested on a real Mac yet. Everything has been written
against what the Mac build of the game should look like, and the first job is
to find out where that guess is wrong. If something goes sideways, that is
the whole point of you being here, and nothing you do can hurt your save.

Your save lives in your home folder, not in the game folder. The setup never
touches it.


Before you start: use the normal Steam branch
---------------------------------------------

In Steam: right-click Space Travel Idle, Properties, Betas. Beta Participation
should say None.

On beta or beta-danger Steam gives a Mac a much older game (0.2.2, not 0.3.5).
Neither the community version nor this patch fits it. If you are on one of
them, pick None and let Steam update the game before you go on. (On Windows
every branch works. It is only the Mac that gets the old game.)


Step 1: Run the check, before anything else
-------------------------------------------

Double-click "Check My Mac Setup.command".

macOS will probably refuse the first time and say it is from an unidentified
developer. That is normal for any script that arrives in a zip. Right-click
the file instead, choose Open, and click Open in the box that appears. You
only have to do that once per file.

If you would rather not fight Finder at all, open Terminal and run this
instead (drag the file into the Terminal window to get the path right):

    sh "/path/to/Check My Mac Setup.command"

It changes nothing. It just looks around and writes
space-travel-idle-mac-report.txt to your Desktop. Send that back before you
run the setup. It answers a lot of questions in one go: where Steam put the
game, what the app bundle is called, whether the game is Intel or Apple
Silicon, and how Apple signed it.


Step 2: Run the setup
---------------------

Close the game first. Then double-click "Setup Space Travel Idle Mod.command",
with the same right-click and Open trick if macOS complains.

It asks the same questions the Windows version asks. Press Enter to install all
44, or c to pick which ones you want. Some names in that list are hidden so it
does not spoil content you have not reached yet, and s shows you the real ones.
If it cannot find the game by itself, it asks for the folder,
and you can drag the folder straight from Finder into the Terminal window.

Point it at the FOLDER that holds Space Travel Idle.app, not at the app
itself. If you drag the app in anyway it works it out and steps up a level.

It needs Python 3 and one Python package called UnityPy. If UnityPy is
missing it offers to install it for you and you just say yes.


Step 3: The one step the setup cannot do for you
------------------------------------------------

This is the part that is different from Windows, and the mod does nothing
without it.

On Windows the mod loader hooks itself into the game just by sitting in the
folder. On a Mac it cannot. The game has to be started through a small script
instead, and only Steam can be told to do that.

The setup prints the exact line to use when it finishes. It looks like this:

    "/Users/you/Library/Application Support/Steam/steamapps/common/Space Travel Idle/run_bepinex.sh" %command%

In Steam: right-click Space Travel Idle, Properties, General, and paste it
into Launch Options. Keep the quotes and keep the %command% at the end.

Then start the game from Steam as normal.


Did it work?
------------

If it did, there is a new folder called BepInEx inside the game folder with a
file called LogOutput.log in it. Open that and the top of it lists every
plugin that loaded. In the game itself, Settings gets a Community mod section
at the bottom of the right hand column.

If the game starts but LogOutput.log never appears, the loader is not getting
in. That is the risk I most expect to hit, and it is almost always one of two
things:

Quarantine: macOS marks everything that came out of a downloaded zip as
untrusted, and it refuses to load an untrusted library. The setup tries to
clear that flag by itself. If it could not, run this in Terminal, with your
own game path:

    xattr -dr com.apple.quarantine "/path/to/Space Travel Idle"

Code signing: if Apple signed the game with something called the hardened
runtime, macOS blocks the loader on purpose and there is no flag to clear.
The check script reports this, which is why step 1 matters. Do not start
pulling signatures off the app on your own. Send me the report and I will
tell you what to do.

Either way, send me these two things and I can usually tell what happened
without guessing:

    The game folder/BepInEx/LogOutput.log
    ~/Library/Logs/Ayatsuji/SpaceTravelIdle/Player.log

To get to that second one: in Finder press Cmd+Shift+G, paste the path, and
press Enter.


Taking it all off again
-----------------------

Run the setup again and choose r. It puts the original game files back and
removes the loader. Then clear the Launch Options line in Steam, or the game
will try to start through a script that is no longer there.

Steam verifying or updating the game also undoes the mod. Just run the setup
again afterwards.


Repairing a scrambled priority list
-----------------------------------

This is the one repair job the setup cannot do for you, because it is your
save that needs fixing rather than the game.

There was a bug in an earlier version of Auto Start where a research or
building rebuilt on load could end up at the bottom of the priority list,
under your Accumulation Layers, and the mod would then remember it there. The
cause is fixed. A list that already got scrambled stays scrambled though,
because the wrong order is what got written down.

If that happened to you, there is a tool in the zip called
tools/repair_priority_order.py. It copies one planet's order out of a save
slot you know was good and writes it back into your current one. It only
touches that one block, it backs the save up first, and it refuses to run
while the game is open.

It needs one more Python package than the setup does. In Terminal:

    python3 -m pip install pycryptodome

Then, with the game closed:

    python3 "/path/to/the/unzipped/folder/tools/repair_priority_order.py" --help

It looks for your saves in ~/Library/Application Support/Ayatsuji, which is
where the Mac build should be putting them. Should. If it says it cannot find
a save folder, tell me where yours actually is, and in the meantime you can
point it there yourself by adding --save-dir "/the/folder/with/your/sti/files"
to the command.

Tell me which planet and which save slot before you run it for real. The tool
asks for the planet as a number, and guessing at that number is the one way to
make things worse rather than better.


What is different from the Windows version
------------------------------------------

Nothing, in terms of what the mod does. Same patches, same plugins, same
settings. The only real difference is the Launch Options line in step 3.

The Balancer
------------

I tuned this patch with a second mod on, the Unlocker by Berserker. I call it
the Balancer. Without it and my settings, I lost every high level fight,
trips took twice as long and Big Bang paid nothing unless I beat my best
score.

The setup now installs it for you, with the settings I used. Both lines are on
when the menu opens. Rather play the plain game? Untick "Balancer". Version
0.2 will be balanced for that too.

If you already have it, your own copy and settings are kept aside. Your
settings come back if you untick mine, and your copy comes back when you
choose r.
